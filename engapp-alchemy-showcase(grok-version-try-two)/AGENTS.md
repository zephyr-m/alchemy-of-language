# Правила работы с EngApp

Перед изменением проекта полностью прочитать [ARCHITECTURE.md](./ARCHITECTURE.md). Перед работой над интерфейсом также прочитать и обновлять [SCREENS.md](./SCREENS.md).

## Обязательные правила

- Showcase и существующая дизайн-система — источник истины для интерфейса.
- Сначала найти и переиспользовать существующий компонент или визуальный паттерн.
- Компонент извлекается из showcase в реальный модуль; showcase и приложение используют один экземпляр компонента.
- Не создавать параллельные компоненты и стили поверх уже выполненной работы.
- Перед визуальной правкой явно перечислить существующие части, которые будут переиспользованы.
- Страницы занимаются композицией. Бизнес-правила находятся в чистых TypeScript-модулях.
- Pinia хранит общее состояние, но не служит контейнером для всей бизнес-логики.
- Компоненты не работают напрямую с API, `localStorage` или IndexedDB.
- Новые папки и абстракции создаются только для существующей задачи.
- Галочка экрана в `SCREENS.md` ставится только после реализации, подключения к маршруту и визуальной проверки пользователем.
- Не запускать установку зависимостей, dev-сервер или сборку. Команды для запуска передавать пользователю.
